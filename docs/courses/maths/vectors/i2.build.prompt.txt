## The explanation Dan reads after playing (use the same words for the same things)
A vector on a flat page splits into two parts at right angles, one along each axis. These parts are its components: the separate x, y and z values of the vector. Take arrow a again, 3 across and 4 up. Its across part runs along the x-axis. Its up part climbs from there to the tip. Drawn nose to tail, the two parts end exactly at the arrow's tip. So together they are the arrow itself, described along the axes. They are not extra pulls. The two parts and the arrow close a right-angled triangle. The arrow is its long side. You can write the parts as a column, 3 above 4. Or you can write them as 3i + 4j. Here i is the unit vector along the x-axis. And j is the unit vector up the y-axis. So 3i + 4j means 3 lots of i, then 4 lots of j.

Often you know the size and an angle instead. Then the triangle gives you the parts. Take a 10 N pull at 30° above the x-axis. The angle sits between the arrow and the across side. In a right-angled triangle, the side next to an angle is the long side times the angle's cosine. So the across part is 10 cos 30° = 8.66 N. The side opposite the angle is the long side times its sine. So the up part is 10 sin 30° = 5 N. Finding the parts this way is called resolving the pull. Each part is shorter than the arrow, unless the arrow lies along an axis. Then one part is the whole arrow and the other is zero. A bearing shows why it matters which side sits next t…

## The house kit (complete API reference)
You write the BODY of one page: HTML, an optional `<style>`, then one inline `<script>` ending
with `K.ready()`. It runs in a sandboxed iframe on Dan's phone (about 340 px wide, touch) and
laptop, with the global `K` and the kit's stylesheet. No network or storage: no web
addresses, `fetch`, `localStorage`, `alert` or `prompt`.

### Page shape that works
1. `<p class="lead">`: one line saying what is drawn (the app adds title and action).
2. The main visual with its controls right under it: `K.stage('#scene', '#controls')` keeps the
   pair on one phone screen. A choice that re-sorts the picture may sit above it.
3. `<p class="say">`: one sentence that changes with the state and says why. Then
   `<div class="k-readouts">` for numbers the drawing does not label.
4. Secondary figures and anything that grows go below.
5. `<p class="caption">`: one short sentence, at most 20 words: where the numbers come from ("A

### Keep the answer hidden until Dan moves
Dan predicts before he plays: open on a setting the question is not about, and hide whatever
gives the answer away until his first move:
- class `k-after-move` on any element (a mark, an arrow, a sentence): hidden, its space kept.
  Hide the answer, not the controls or a whole figure (a blank hole fails the test).
- `K.readout({..., afterMove: true})` shows "?" until then; plot series and marks take `afterMove: true` too.
- `K.moved` is true from then on: in `K.update`, write `K.moved ? answer : question`.

### The pipeline
Controls register themselves; their values form `params` = `{id: value}`.
```
K.model(fn)        fn(params) -> outputs {name: number | string}. Pure: no DOM, no lists or objects.
K.update(fn)       fn(params, outputs): draw everything here. More than one is allowed.
K.at(over)         -> outputs of the model at those params (others take each control's starting value)
K.check(label, fn, {source?})   fn() must return exactly true
K.ready()          call once, last: draws the opening state and runs the checks
K.complete()       at the lesson's end
K.params()  K.outputs()  K.refresh()   (refresh reruns the pipeline after you change your own state)
```
A readout whose id is an output key updates itself.

### Controls
Every control takes `into` (a selector or element). Ids are unique; use the lesson's ids exactly.
```
K.control({id, label, min, max, step, value, unit?, prefix?, fmt?, log?, snap?, hint?, into}) -> {el, get(), set(v)}
K.choice({id, label, options: [value | {value, label}], value, hint?, into}) -> {el, get, set}
K.toggle({id, label, value: false, hint?, into}) -> {el, get, set}
K.stepper({id, steps: [title | {title, text}], value: 0, compact?, label?, into}) -> {el, get, set, setSteps(list)}
K.button({label, press, secondary?, into}) -> {el, press(), setLabel(text)}
K.drag(el, {control, toValue(x, y)}) -> {el}
```
`control` is a big slider with − / + buttons. Keep `unit` short; `fmt(v)` returns the whole text;

content). `button` is an action (Send it in): use it, not plain buttons. `drag` lets Dan move

to the control's value; the first touch counts as his move.

### Example
```html
<p class="lead">Lengthen the string and watch each swing take longer.</p>
<div id="plot"></div>
<div class="k-controls" id="controls"></div>
<p class="say" id="say"></p>
<div class="k-readouts" id="outs"></div>

<script>
  const g = 9.81;
  const period = (L) => 2 * Math.PI * Math.sqrt(L / g);
  K.control({ id: 'L', label: 'String length', min: 0.1, max: 3, step: 0.05, value: 1, unit: 'm', snap: [2], into: '#controls' });
  K.stage('#plot', '#controls');
  K.readout({ id: 'T', label: 'One full swing takes', unit: 's', decimals: 2, into: '#outs' });
  const plot = K.plot('#plot', { x: { min: 0, max: 3, label: 'Length (m)' }, y: { min: 0, max: 4, label: 'Period (s)' } });
  K.model((p) => ({ T: period(p.L) }));
  K.update((p, o) => {
    plot.draw({ series: [{ fn: period }], marks: [{ x: p.L, y: o.T, guides: true }] });
    document.getElementById('say').textContent = !K.moved ? 'Make the string four times longer: how much longer is each swing?'
      : 'A ' + K.fmt(p.L, { decimals: 2 }) + ' m string swings there and back every ' + K.fmt(o.T, { decimals: 2 }) + ' s. Four times the length only doubles that.';
  });
  K.check('No length, no swing time', () => K.near(period(0), 0));
  K.check('A seconds pendulum (2 s per swing) is 0.994 m long', () => K.near(period(0.994), 2, 0.002),
    { source: 'https://en.wikipedia.org/wiki/Seconds_pendulum' });
  K.check('Four times the length doubles the period', () => K.near(K.at({ L: 2 }).T / K.at({ L: 0.5 }).T, 2, 1e-9));
  K.ready();
</script>
```

<script>
  // gamma: ratio of specific heats for air, the value NASA Glenn's Brayton page uses.
  const GAMMA = 1.4;
  const SOURCE = 'https://www.grc.nasa.gov/www/k-12/airplane/brayton.html';
  const pct = (r) => 100 * (1 - Math.pow(r, -(GAMMA - 1) / GAMMA));

  const r = K.control({ id: 'r', label: 'Pressure ratio', hint: 'Pressure after the compressor ÷ pressure before it', min: 1, max: 50, step: 1, value: 8, unit: ':1', into: '#controls' });
  K.readout({ id: 'eff', label: 'Ideal efficiency', unit: '%', decimals: 1, big: true, into: '#outs' });

  K.stage('#plot', '#controls');   // stacked on a phone, side by side on a laptop

  const plot = K.plot('#plot', {
    x: { min: 1, max: 50, label: 'Pressure ratio' },
    y: { min: 0, max: 100, label: 'Ideal efficiency (%)' },
    label: 'Ideal efficiency rises steeply at low pressure ratios, then flattens',
  });

  // The pure model: pressure ratio -> ideal efficiency in percent.
  K.model((p) => ({ eff: pct(p.r) }));

  K.update((p, o) => {
    plot.draw({
      series: [{ fn: pct, label: 'Ideal efficiency' }],
      marks: [{ x: p.r, y: o.eff, guides: true }],   // its value is in the readout alone
    });
    document.getElementById('work').style.width = o.eff + '%';
    document.getElementById('split').setAttribute('aria-label', 'The filled part becomes work: ' + (o.eff < 50 ? 'under' : 'over') + ' half the heat');

    let s;
    if (p.r === 1) {
      s = 'With no squeeze at all (r = 1), the hot gas has no extra pressure to push the turbine with, so no work comes out: 0%.';
    } else if (p.r * 2 <= 50) {
      const more = pct(p.r * 2) - o.eff;
      s = 'At ' + p.r + ':1 an ideal engine turns ' + o.eff.toFixed(1) + '% of the fuel\'s heat into work. Doubling the squeeze to ' +
        p.r * 2 + ':1 would add ' + more.toFixed(1) + ' more points.';
    } else {
      const less = o.eff - pct(p.r / 2);
      s = 'At ' + p.r + ':1 an ideal engine turns ' + o.eff.toFixed(1) + '% of the fuel\'s heat into work. Halving the squeeze would cost only ' +
        less.toFixed(1) + ' points: the curve has flattened.';
    }
    // Until Dan moves the slider the sentence invites rather than answers his prediction.
    document.getElementById('say').textContent = K.moved ? s : 'Does doubling the squeeze double the work you get? Move the pressure ratio and see.';
  });

  // Known answers, worked out by hand from the formula.
  K.check('No squeeze (r = 1) gives 0% efficiency', () => K.near(K.at({ r: 1 }).eff, 0, 1e-9));
  K.check('r = 10 gives 48.2%, from the ideal Brayton formula', () => K.near(K.at({ r: 10 }).eff, 48.205, 0.001), { source: SOURCE });
  K.check('Efficiency rises with every step up in pressure ratio', () => {
    for (let x = 1; x < 50; x++) if (!(K.at({ r: x + 1 }).eff > K.at({ r: x }).eff)) return false;
    return true;
  });
  K.check('Diminishing returns: 1 → 2 adds 18.0 points, 20 → 40 adds only 7.6', () =>
    K.near(K.at({ r: 2 }).eff - K.at({ r: 1 }).eff, 17.97, 0.01) && K.near(K.at({ r: 40 }).eff - K.at({ r: 20 }).eff, 7.63, 0.01));
  K.check('Even at r = 50 the ideal stays below 100% (67.3%)', () => K.near(K.at({ r: 50 }).eff, 67.30, 0.01));

  K.ready();
</script>
