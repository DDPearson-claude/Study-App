The c handle is a round dot where the line crosses the y-axis, and it slides up and down the axis. The m handle sits on the line 1 along from that crossing, with a small step drawn under it, 1 across and m up or down, and dragging it up or down turns the line about the crossing. c snaps to whole numbers and m to halves. Above the grid the rule y = mx + c is written with the two numbers in, and it rewrites as either handle moves. c is the y at the crossing, because there x is 0, so m × x is 0 and only c is left. m is the climb for each 1 along, so it is the small step's rise. Where the line crosses the x-axis a small diamond marks it, the x-intercept, a different shape from the round c dot so the two are not mixed up. It sits where y = 0. When m is 0 the line lies level and the diamond goes, because a level line never crosses the x-axis: it misses it, or, as y = 0, lies along it. A test point can be dragged to any whole-number point. A readout puts its x into the rule, such as 2 × 3 + 1 = 7, and the point lights up \"on the line\" only when the answer is its y. On the parallel screen a faint copy of the starting line stays put while c slides, so you can see the gap between them stay the same all the way along. Some screens show an idea and the rest ask you to try it. A puzzle shows a rule or a line and three answers.
