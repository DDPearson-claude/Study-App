## The explanation Dan reads after playing (use the same words for the same things)
Cells joined in series make a string. One current flows through every cell. So each cell gives the same ampere-hours, hour by hour. The cell that holds the fewest runs out first, and then the string is finished. Charge the string from flat, and the same cell is full first. Either way, the weak cell is the one pushed too far.

Picture six cells as tanks. Five hold 100 Ah. One faded cell holds, say, 80 Ah. Draw 10 A from the string. The current has only one path, so every cell gives 10 Ah each hour. After 8 hours the small cell has given its 80 Ah and is empty. The big cells still hold 20 Ah each. But every amp must pass the empty cell to reach the load. So the string gives 80 Ah, not 100.

Keep the load on, and the five strong cells push the same current through the empty one. It has nothing left to give. So the current drives it backwards, and its voltage turns round. This is cell reversal. It can leave the cell with a permanent short. In a long string, one cell is a small part of the total. So the total can look healthy while one cell is being reversed.

A deep discharge can leave every cell flat. Now charge the string from flat at 10 A, and the story runs the other way. After 8 hours the small cell is full. ### The pipeline
Controls register themselves; their values form `params` = `{id: value}`.
```
K.model(fn)        fn(params) -> outputs {name: number | string}. Pure: no DOM, no lists or objects.
K.update(fn)       fn(params, outputs): draw everything here. More than one is allowed.
K.at(over)         -> outputs of the model at those params (others take each control's starting value)
K.check(label, fn, {source?})   fn() must return exactly true
K.ready()          call once, last: draws the opening state and runs the checks
K.complete()       at the lesson's end
K.params()  K.outputs()  K.refresh()   (refresh reruns the pipeline after you change your own state)
```
A readout whose id is an output key updates itself.

### Controls

content). `button` is an action (Send it in): use it, not plain buttons. `drag` lets Dan move
the thing itself: `toValue` maps the pointer (viewBox units; px from `el`'s top-left for HTML)
to the control's value; the first touch counts as his move.
